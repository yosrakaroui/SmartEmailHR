1. Présentation du projet
1.1 Description générale
SmartEmail HR est une plateforme web complète de gestion intelligente du recrutement. Elle couvre l'intégralité du cycle de recrutement : de la création de l'offre d'emploi par le responsable RH, jusqu'à l'envoi automatique des réponses aux candidats, en passant par la collecte automatisée des candidatures par email, l'analyse par intelligence artificielle et la visualisation structurée sur un tableau de bord.
La plateforme repose sur quatre piliers technologiques : Angular (frontend), ASP.NET Core (backend), n8n (automatisation des workflows), et l'API Groq — LLaMA 3 (intelligence artificielle, 100 % gratuite). Chaque candidature reçue par email est automatiquement collectée par n8n, transmise au backend, analysée par Groq, scorée et classée — permettant au RH de se concentrer uniquement sur la prise de décision. L'architecture est pensée pour une séparation stricte des responsabilités : n8n transporte, le backend orchestre, Groq analyse.
Pourquoi ce projet est fort : Il automatise l'intégralité du recrutement, réduit le biais humain grâce à l'IA, combine 4 technologies modernes dans un cas d'usage réel et valorisable, et reste réalisable dans un cadre académique par des étudiants débutants en IA et n8n.
1.2 Objectifs du projet
Permettre au RH de créer et gérer des offres d'emploi structurées par domaine.
Collecter automatiquement les candidatures reçues par email via n8n.
Analyser et scorer chaque CV par intelligence artificielle en le comparant aux exigences du poste.
Classer automatiquement les candidats par catégorie/domaine et par score de pertinence.
Offrir au RH une interface claire pour consulter les candidats et prendre ses décisions.
Automatiser l'envoi des emails de réponse (acceptation / refus) après validation du RH.
Gérer automatiquement la fin d'une offre : refus automatique de toutes les candidatures ultérieures.
Fournir un tableau de bord administrateur avec des statistiques globales sur le recrutement.

2.2 Justification des choix
Angular 17+
Framework frontend de Google, très utilisé en entreprise pour les dashboards et back-offices. Il impose une structure claire avec TypeScript, réduisant les erreurs. Angular Material fournit des composants UI prêts à l'emploi (tableaux, formulaires, onglets, cartes), ce qui accélère considérablement le développement du tableau de bord RH.
ASP.NET Core 8
Framework backend Microsoft, performant et structuré. Il permet de créer des API REST propres en C#, avec une intégration native de JWT pour l'authentification et d'Entity Framework Core pour la gestion de la base de données. Son écosystème riche facilite l'intégration de Groq via HttpClient.
SQL Server / PostgreSQL
Base de données relationnelle robuste et compatible avec Entity Framework Core. Le schéma relationnel (Offres → Candidatures → Analyses) est naturellement adapté à un modèle SQL, garantissant l'intégrité des données et la cohérence des liens entre entités.
n8n
Outil d'automatisation visuel open source (self-hosted ou cloud). n8n fonctionne par workflows composés de nœuds connectés graphiquement. Dans ce projet, il joue le rôle d'orchestrateur de données : il surveille la boîte Gmail/IMAP, extrait les pièces jointes PDF, lit leur contenu textuel, envoie les données au backend via HTTP POST, et reçoit des webhooks du backend pour déclencher l'envoi d'emails via Gmail/SMTP. Son interface en glisser-déposer le rend accessible à des débutants sans expérience en code. n8n n'intègre aucune intelligence artificielle et n'appelle jamais l'API Groq — il est exclusivement un transporteur et déclencheur de tâches.
Groq (LLaMA 3)
Groq est une plateforme d’inférence IA ultra-rapide qui propose un accès gratuit (via groq.com) aux grands modèles de langage open source, notamment LLaMA 3.3 70B et Mixtral 8x7B. Contrairement à OpenAI (payant dès le premier appel), Groq offre un tier gratuit généreux adapté aux projets académiques : environ 14 400 requêtes par jour sur LLaMA 3. L’API Groq est 100 % compatible avec le format de l’API OpenAI, ce qui permet de l’intégrer dans le backend ASP.NET Core avec un simple changement de base URL (https://api.groq.com/openai/v1) et de clé API. Le modèle reçoit le texte du CV et les exigences du poste, et retourne un JSON structuré contenant le score (0-100 %), le résumé des compétences, la décision suggérée et la classification par domaine. Il génère également le contenu des emails de réponse. Coût : 0 € pour un usage académique dans les limites du tier gratuit.

3.3 Collecte automatique des candidatures (n8n)
Dès qu'un candidat envoie un email à l'adresse RH de l'entreprise, le workflow n8n prend en charge le traitement automatique sans aucune intervention humaine. Il est fondamental de comprendre le rôle précis de n8n dans ce système : n8n n'appelle jamais l'IA directement. n8n joue le rôle d'un facteur intelligent — il collecte les données (emails entrants), les livre au backend, et distribue les réponses (emails sortants). L'analyse par IA est exclusivement effectuée par le backend ASP.NET Core, qui est le seul à communiquer avec l'API Groq.
Le trigger IMAP de n8n surveille en permanence la boîte mail de l'entreprise.
À la réception d'un email, n8n extrait : l'objet de l'email (pour identifier le poste visé), l'adresse email et le nom de l'expéditeur, le fichier PDF joint (CV).
n8n lit le texte brut du PDF via le nœud intégré de lecture PDF.
n8n envoie une requête HTTP POST vers le backend avec toutes ces données.
Règle fondamentale du système — n8n ne touche jamais l'IA. n8n ne fait que transporter des données. Groq est appelé uniquement par le backend ASP.NET Core. Pensez à n8n comme un facteur et à Groq comme un expert : le facteur (n8n) collecte le courrier (emails entrants), le livre au bureau (backend), et envoie les réponses (emails sortants) — il ne sait pas analyser un CV. L'expert (Groq) est dans le bureau (backend) : c'est lui qui analyse, score et rédige. Le bureau (backend) est le chef d'orchestre : il reçoit du facteur, consulte l'expert, range les résultats, et redonne au facteur ce qu'il faut envoyer.
3.4 Traitement et stockage des candidatures (Backend)
À la réception des données envoyées par n8n, le backend ASP.NET Core effectue les opérations suivantes :
Réception et validation des données (email, objet, texte du CV).
Identification du poste visé en comparant l'objet de l'email aux offres actives en base.
Création d'un enregistrement Candidature lié à l'offre correspondante.
Appel de l'API Groq avec le texte du CV et les exigences du poste (voir section 3.5).
Stockage de l'analyse IA (score, résumé, classification, compétences détectées).
Mise à jour du statut de la candidature : En attente de décision RH.

Le titre du poste, la description, les compétences requises et le niveau d'expérience attendu (issus du formulaire RH).

3.8 Envoi automatique des emails de réponse (n8n)
Lorsque le RH clique sur « Accepter » ou « Refuser », le système déclenche automatiquement un workflow n8n qui gère l'envoi de l'email de réponse.
Flux d'acceptation
Le RH clique sur « Accepter ».
Le backend appelle l'API Groq (LLaMA 3) pour générer le contenu de l'email d'acceptation, personnalisé avec le nom du candidat, le poste visé et une proposition de planification d'entretien.
Le backend appelle le webhook n8n avec les données de l'email.
n8n envoie l'email au candidat (via SMTP ou Gmail) avec une proposition de planification d'entretien.
Le statut du candidat est mis à jour : Accepté.
Flux de refus
Le RH clique sur « Refuser ».
Le backend appelle l'API Groq (LLaMA 3) pour générer un email de refus courtois et personnalisé, incluant le nom du candidat et le poste visé.
Le backend appelle le webhook n8n.
n8n envoie l'email de refus au candidat.
Le statut du candidat est mis à jour : Refusé.
Étape de validation obligatoire : avant tout envoi, l'email généré par Groq est affiché dans une modale Angular visible par le RH. Le RH peut lire le contenu, le modifier si nécessaire, puis cliquer sur « Confirmer l'envoi ». Ce n'est qu'après cette confirmation que le backend appelle le webhook n8n pour déclencher l'envoi réel via Gmail/SMTP. n8n reçoit uniquement les données finales (destinataire, sujet, corps) — il ne génère rien, il envoie.
3.9 Gestion de la fin d'une offre
Lorsqu'un recrutement est terminé ou que l'offre a expiré, le système applique automatiquement une règle de fermeture.
Le RH peut manuellement désactiver ou supprimer une offre depuis le tableau de bord.
Les offres dépassant leur date d'expiration sont automatiquement désactivées.
Tous les emails reçus pour une offre désactivée sont automatiquement refusés par n8n, sans intervention du RH.
Un email de refus automatique est envoyé au candidat indiquant que le poste n'est plus disponible.
Les candidatures reçues après la fermeture restent visibles dans le dashboard à des fins d'archivage.

7. Workflows n8n
7.1 Workflow 1 — Réception des candidatures
Ce workflow est actif en permanence. Il surveille la boîte email de l'entreprise et traite automatiquement chaque nouvelle candidature. Rappel fondamental : ce workflow ne fait que collecter et transporter des données vers le backend. Il n'appelle jamais l'API Groq. La chaîne exacte est la suivante : (1) détection du nouvel email via IMAP, (2) extraction du fichier PDF joint, (3) lecture du texte brut du PDF via le nœud natif n8n, (4) envoi de toutes les données au backend via une requête HTTP POST contenant { nom, email, objet_email, texte_cv }, puis le backend prend le relais pour l'analyse IA.
Nœud n8n
Type
Configuration
1. Email Trigger
IMAP / Gmail Trigger
Connexion à la boîte mail, déclenchement à chaque email avec pièce jointe PDF.
2. Extract PDF
Binary Data Extract
Extraction du fichier PDF joint.
3. Read PDF Text
PDF Read (nœud natif)
Extraction du texte brut depuis le PDF.
4. Set Variables
Set Node
Préparation des données : objet email, email expéditeur, texte CV.
5. HTTP Request
HTTP Request Node
POST vers /api/candidatures/recevoir avec les données extraites.
6. IF — Succès ?
IF Node
Vérification du code de retour HTTP (200 = succès).
7. Error Log
Set + HTTP Request
En cas d'erreur, envoi d'une alerte à l'Admin.
7.2 Workflow 2 — Envoi email d'acceptation
Déclenché par un webhook appelé depuis le backend, après que le RH a confirmé sa décision dans la modale Angular. À ce stade, le contenu de l'email a déjà été généré par Groq et validé par le RH. n8n reçoit uniquement les données finales prêtes à envoyer — il ne génère aucun contenu.

7.3 Workflow 3 — Envoi email de refus
Identique au workflow 2 dans son fonctionnement, mais déclenché lors d'un refus. 7.4 Workflow 4 — Refus automatique (offre expirée)
Ce workflow est déclenché automatiquement chaque jour via un planificateur (Cron Trigger). Il vérifie les offres expirées et envoie des emails de refus automatiques aux candidats encore en attente. Particularité importante : le contenu de l'email de refus automatique est un texte fixe prédéfini directement dans n8n — il n'appelle pas Groq, car il n'y a pas de RH disponible pour valider un contenu généré par l'IA dans ce cas. C'est le seul workflow où n8n contient lui-même le contenu du message.

8. Contraintes et exigences
8.1 Contraintes techniques
L'application doit fonctionner en local (localhost) sans déploiement cloud obligatoire.
n8n doit être installé en local via Docker ou npm.
La base de données SQL Server ou PostgreSQL doit être accessible en local ou via un service gratuit.
La clé API Groq ne doit jamais être exposée côté frontend (stockée dans appsettings.json ou .env, hors Git).
Toutes les données sensibles doivent être dans des fichiers de configuration exclus du versionnement (.gitignore).
8.2 Contraintes académiques
Projet réalisable en 5 à 7 semaines par des étudiants de 2ème année d'ingénierie.
Technologies accessibles : Angular, .NET, n8n et Groq sont tous documentés avec des tutoriels débutants.
Code source versionné sur GitHub ou GitLab.
README.md complet avec instructions de démarrage étape par étape.
Données de démonstration (offres et candidats fictifs) incluses pour la soutenance.
8.3 Exigences de sécurité
Les mots de passe sont hashés avec bcrypt (minimum 10 rounds).
Toutes les routes protégées vérifient la validité et l'expiration du token JWT.
Les routes Admin sont inaccessibles aux utilisateurs RH (vérification du rôle).
Les requêtes de n8n vers le backend sont authentifiées par un en-tête secret partagé.
8.4 Exigences de performance
Réponses API standard (lecture, mise à jour) : inférieures à 2 secondes.
Analyse IA d'un CV : jusqu'à 5 secondes (Groq est significativement plus rapide qu'OpenAI grâce à ses puces LPU dédiées). Un spinner de chargement doit être affiché.
Génération du contenu d'un email : jusqu'à 5 secondes. Un indicateur de chargement doit être affiché.

Terme

Angular
Framework JavaScript/TypeScript de Google pour créer des interfaces web dynamiques (SPA).
ASP.NET Core
Framework backend Microsoft pour créer des API REST en C#.
Entity Framework Core (EF Core)
ORM qui traduit les classes C# en tables SQL, évitant d'écrire du SQL manuellement.
JWT
JSON Web Token. Jeton chiffré contenant les infos d'un utilisateur connecté, utilisé pour sécuriser les routes.
n8n
Outil d'automatisation de workflows open source avec interface visuelle. Aucune IA intégrée.
Webhook
URL spéciale qui reçoit des données envoyées par un autre service. Utilisé pour déclencher n8n depuis le backend.
Groq (LLaMA 3)
Modèle d'IA accessible via une API HTTP. Analyse les CV, attribue des scores et génère des textes.
IMAP
Protocole permettant à n8n de surveiller et lire les emails d'une boîte mail.
SMTP
Protocole d'envoi d'emails, utilisé par n8n pour envoyer les réponses aux candidats.
SPA
Single Page Application. Application web dont le contenu se charge dynamiquement sans rechargement de page.
ORM
Object-Relational Mapper. Outil qui traduit les objets du code en lignes dans une base de données relationnelle.
Score IA
Note de 0 à 100 % attribuée par l'IA mesurant l'adéquation du CV avec les exigences du poste.
bcrypt
Algorithme de hachage pour stocker les mots de passe de manière sécurisée et irréversible.
Guard Angular
Mécanisme Angular qui protège les routes de l'application (vérifie si l'utilisateur est connecté et a le bon rôle).
Parsing PDF
Extraction du texte brut contenu dans un fichier PDF pour permettre son analyse par l'IA.
